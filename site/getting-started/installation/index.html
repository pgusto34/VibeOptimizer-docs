Install & configure

VibeOptimizer’s Python CLI runs on a Linux host with local CPU workers and access to a supported Slurm GPU node. You do not need Node.js unless you are building this documentation site.

Prerequisites

Section titled “Prerequisites”

CPU workers need enough memory and writable storage for builds and exports. Docker’s storage filesystem may differ from the run filesystem; check both. Avoid sharing mutable build directories between concurrent runs unless the cache explicitly supports it.

Clone and install

Section titled “Clone and install”

The pinned roofline-guided-agent-benchmark Python dependency is installed from Git over SSH. The environment must be authorized to access that repository; a Git authentication failure is not a GPU or simulator issue. Install uv using its official installation instructions.

The clone already includes the pinned benchmark and VibeSim submodules. Existing cases can use the included benchmark directory; neither dependency requires another clone. Campaign repository points to that local case directory, not to the framework Git URL.

Use an isolated benchmark checkout when authoring new cases or changing a catalog used by a frozen campaign. That checkout must remain compatible with the pinned dependency and case schemas. The field references identify the pinned contract.

Configure local state

Section titled “Configure local state”

Process environment overrides .env.live. Campaign paths can contain ${VARIABLE} substitutions; undefined variables are errors. Relative campaign paths resolve from the campaign file, while runtime settings resolve through their loader. Keep .env.live, credentials and generated runs out of Git.

StateGuidance
Model snapshotsImmutable, pinned revisions; share read-only when compatible
Build and kernel cachesPreserve compatible caches; use private writable namespaces

Some preparation workflows use VIBEOPTIMIZER_IMMUTABLE_MODEL_CACHE and VIBEOPTIMIZER_AUTH_SOURCE to seed immutable model and authentication inputs. Set them only when the chosen preparation requires them; they do not replace image, model or harness configuration.

Prepare images and authentication

Section titled “Prepare images and authentication”

Authenticate your selected agent CLI and make its credentials available through the declared harness mounts. Model providers may require API credentials; gated model downloads may require HF_TOKEN. Never place credential values in case files or documentation.

The case’s engine image must contain the expected serving framework, Python interpreter and build dependencies. The harness and analysis images must match the configured topology. Preparation can build patched VibeSim binaries automatically from the submodule; it does not bootstrap every engine image or model for you.
