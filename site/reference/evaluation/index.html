Evaluation YAML

Controller-private focused-probe and historical-recovery policy. This information must not be passed to the optimizer as an answer key.

Reading defaults: these are literal schema defaults. An omitted optional block is not the same as an empty block. Fields inside a block are required only when that block/variant applies. Effective launcher behavior and cross-field rules are described below.

Controller-private evaluation example

Section titled “Controller-private evaluation example”

Reference this file from the campaign’s evaluation field. This minimal policy leaves focused module targets and historical latency recovery disabled while final correctness and serving gates remain configured in the campaign. Add real model module paths and measured before/after latencies only when those optional checks are required; never expose the answer key to the optimizer.

Conditions and effective behavior

Section titled “Conditions and effective behavior”
  • Before/after target latencies are supplied together and require target names; after_us must be smaller than before_us.
  • Region baseline latencies require a named enclosing region and appear as a before/after pair.
  • The loader also supports architecture-specific latency blocks under architectures.<architecture>; do not mix these latency fields at the top level and under architectures. The selected architecture’s fields map to the model above.
  • After source/image identity must match the case’s historical references. Optimize mode does not require an unknown after result.
  • A case without focused module targets still requires independent applicable correctness and serving gates.
