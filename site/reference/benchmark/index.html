Benchmark YAML

Serving workload fields and the catalog’s schema-2 wrapper. Read the case/workload guide before choosing lengths and concurrency.

Reading defaults: these are literal schema defaults. An omitted optional block is not the same as an empty block. Fields inside a block are required only when that block/variant applies. Effective launcher behavior and cross-field rules are described below.

Serving workload example

Section titled “Serving workload example”

Conditions and effective behavior

Section titled “Conditions and effective behavior”
  • The optimizer currently accepts generated input with objective output_throughput from catalog schema 2; dataset-file variants in the catalog table are not a promise of optimizer support.
  • request_rate must be positive and finite or the string inf.
  • Requested prompt and output lengths must fit engine context, including framework-specific reserved capacity.
  • Model and framework commits are immutable full revisions.
  • Workload benchmark.repetitions, final performance.repetitions, and profiling capture counts are separate settings. New simulator captures profile one workload repetition by default; final serving keeps its configured policy.
